# RDK X5 芒果疏果视觉程序

程序按比赛流程运行：等待电控发送 `S/s`，顶部相机完成车体对中，随后侧相机判断四个固定位置中哪些是绿色芒果，最后等待下一棵树的 `S/s`。

## 已确认的板端设备

- RDK X5：`192.168.127.10`
- 顶部相机：`5MP USB Camera`，使用唯一的 `/dev/v4l/by-id/...P030D03...` 路径
- 侧边相机：`1080P USB Camera`，使用唯一的 `/dev/v4l/by-id/...P030102...` 路径
- 两台相机：`1280x720 MJPG 30 FPS`
- 40Pin UART1：Pin 8 TX、Pin 10 RX、设备 `/dev/ttyS1`

两台相机型号不同且都有唯一设备路径，换 USB 插口不会认反。当前默认 5MP 相机放顶部、1080P 相机放侧边；若机械安装需要反过来，交换 `config.json` 中 `top.device` 与 `side.device`。

## 接线

RDK X5 与电控必须交叉连接并共地：

| RDK X5 | 电控 |
|---|---|
| Pin 8 UART1_TXD | RX |
| Pin 10 UART1_RXD | TX |
| 任意 GND | GND |

UART 是 `3.3 V TTL`，不能接 RS-232 电平，也不要向信号脚输入 5 V。通信参数固定为 `115200, 8N1`，无流控。

## 串口协议

每条视觉回包以 `\n` 结束；电控触发可以只发一个字节，不要求换行。

| 方向 | 示例 | 含义 |
|---|---|---|
| 电控 -> 视觉 | `S` 或 `s` | 到达一棵新树，开始/重新开始完整流程 |
| 视觉 -> 电控 | `B,1` | 已接收触发，序号 1 开始 |
| 视觉 -> 电控 | `A,1,+23,-8` | 树中心相对画面参考中心：右 23 px、上 8 px |
| 视觉 -> 电控 | `T,1,+32.5` | 树在地面 XY 平面内相对车体 X 轴的朝向角，单位为度 |
| 视觉 -> 电控 | `C,1` | 连续 5 帧进入允许误差，且 `T` 已发送；这是顶部阶段最后的放行信号 |
| 视觉 -> 电控 | `G,1,L1,R2` | 只有 L1、R2 检测为绿色芒果 |
| 视觉 -> 电控 | `G,1,NONE` | 四个位置都没有绿色芒果 |
| 视觉 -> 电控 | `E,1,TREE_NOT_FOUND` | 当前没有可靠检测到树，每秒最多一次 |

`dx > 0` 表示树在画面中心右侧，`dy > 0` 表示树在画面中心下方。电控第一次联调必须低速点动，确认车体运动方向与误差减小方向一致。

`T` 消息的角度范围是 `[-90°, 90°)`：以车体 X 轴正方向为 0°，按图像坐标换算后逆时针为正。它表示树杈/树冠在水平 XY 平面内的旋转角，不是树杈在竖直方向的仰角。若电控需要另一种正负方向，只需在接收端取负号或做一次角度偏置。电控应把 `C` 当作顶部流程的最后放行信号，不要只收到 `T` 就提前进入下一步。

位置编号规定：`L1=左侧较高/外侧`，`L2=左侧较低/内侧`，`R1=右侧较高/外侧`，`R2=右侧较低/内侧`。

## 运行

```bash
cd ~/mango_vision
chmod +x run.sh
./run.sh
```

程序启动后保持等待，电控每到一棵树发一次 `S`。运行期间再次收到 `S/s` 会立即放弃上一轮并从顶部对中重新开始。

运行后，在同一局域网的电脑浏览器打开：

```text
http://192.168.127.10:8080
```

等待 `S/s` 时网页显示顶部相机；进入侧视识别后自动显示侧边相机。网页画面包含顶部中心偏差或侧边四个位置框。关闭网页不会停止视觉程序。若不需要预览，可用 `./run.sh --no-preview`。

不接电控的相机流程测试：

```bash
./run.sh --no-serial --start-now --once
```

拍摄两台相机的原图和标注图：

```bash
python3 tools/camera_check.py
```

结果保存在 `camera_check/`，正常比赛流程的关键帧保存在 `debug/`。

## 安装相机后必须调整

当前代码和协议可以直接运行，但相机尚未装车，下面三项必须用真实比赛树调好：

1. `top_detector.reference_offset_px`：夹爪真正对准树时，树中心相对画面中心的固定偏置。
2. `side_detector.positions`：L1、L2、R1、R2 四个矩形框，数值是画面宽高的 0~1 比例。
3. `top_detector.orientation_offset_deg`：相机画面横轴与车体 X 轴的安装偏角。
4. 两组 `green_hsv_lower/upper`：在固定曝光和固定白平衡后，根据现场灯光调整绿色范围。

如果装车后画面上下颠倒，把对应相机的 `rotate` 改成 `180`；如果左右镜像，把 `flip_horizontal` 改成 `true`。这两个选项只改变图像方向，不改变串口协议。

默认顶部允许误差为 `15 px`，连续 `5` 帧满足才进入侧视阶段。侧视会观察 `15` 帧，某位置至少 `9` 帧检测到绿色才会上报，避免单帧反光误判。

# 标定与检测流程说明

> 因为相机近大远小 + 广角畸变，同一颗果在画面不同位置、不同树倾斜角下成像大小能差 3～4 倍，
> 公式算不准；而拍 14 组图半小时能拍完，量出来的数自带验证。

---

## 1. 为什么必须实测，不能算

- **近大远小**：同样 30mm 的果，离相机 20cm 和 35cm，成像面积差 **3 倍多**。
  我们实测同一棵树同一帧里，两处已知尺寸算出的尺度比就有 **1.39**；四个挂点在画面里的果径实测 **44～84px**。
- **广角畸变**：画面边缘 1 个像素代表的毫米数比中心小，果越靠边越"瘦"。
  我们这台侧视相机的水平视场约 **99°**，边缘畸变不可忽略。
- **倾斜让每个点位的深度都不一样**：树绕竖轴转 0～30°，外侧挂点会往相机方向靠/离，
  同一颗果在自己的点位上就会变大小（实测放大倍数在 1.0～1.9 之间）。
- 用公式解决要：相机内参标定 + 畸变模型 + 那个瞬间的深度 → 赛前做不完，而且**没人能验证它错没错**。
- 实测解决：拿尺子和果拍照，量出来就是对的，错了肉眼就能看出来。

---

## 2. 准备阶段要拍什么

前提：**相机装车、树装车、全部固定死**。相机一旦动过，整张表作废，必须重拍。

树的倾斜角是唯一变量，规则允许 ±30°，我们按 **5° 一档、共 7 档** 拍：

| 档位 | 0° | 5° | 10° | 15° | 20° | 25° | 30° |
|---|---|---|---|---|---|---|---|

每一档拍 **两组**，每组至少 **3 帧**（防手抖/防对焦误差）：

- **A 组 · 四点全挂果**：四个挂点全挂**奶黄果**。
  → 用来量每个点位上果的**外接矩形**，取所有帧里**最大**的那一组。
- **B 组 · 四点全空**：四个挂点都不挂果（磁铁座、粗枝端还在）。
  → 用来量"没有果时这里是什么样"的本底，这是阈值能不能站得住的关键。

额外要求：

1. 每个点位的果**转两次**：一次转到画面里最"胖"，一次最"瘦"（果是椭球，自转就变宽窄）。
2. 存**原始帧**（预览里按 `s`），PNG，**不要截图、不要微信传图**。截图被窗口缩放和 JPEG 压缩过，量出来的尺寸不可信。
3. 背景尽量暗、不要有黄色/奶白色杂物（会进同一套颜色判据）。
4. 文件名带档位（`yaw10_a_1.png` 这种），否则 14 组图分不清。

**为什么用黄果标定、绿果用**：黄果和树不同色，能干净分割出来；而"某档某点位的果在画面哪儿、多大"是**纯几何量，跟颜色无关**。所以标定阶段挂黄果，运行时判绿果。

---

## 3. 从这些图里量出什么

每一档、每个点位，产出 4 个数：

| 量 | 取法 | 为什么这么取 |
|---|---|---|
| 中心坐标 `(x, y)` | 该档所有帧的果心平均 | 后面要在这一带找果 |
| 外接矩形 `w × h` | 取**最大**情况 | 框是"容器"，怎么转都必须框得住；框小了果露一半，面积占比变低 → 漏检 |
| 果径 `R_core` | 最大内接圆半径（不是 `√(面积/π)`） | 果和背景/枝干粘连只会把外框撑大，不会把内接圆撑大 |
| 面积占比 | 果身像素 ÷ 矩形面积 | 判"这里有果"用的门槛 |

**阈值一定按"最小情况"定**：最瘦的角度、最远的点位，那时果身占矩形比例的**最低值**，就是门限的下界；
再拿 B 组（全空）的本底量作为上界，门限落在两者之间。

一句话记法：**框取最大（宁大勿小），阈值取最小（宁低勿高）。**

---

## 4. 运行时怎么用这张表

```
① 俯视相机      → 算出树的倾斜角 ψ（两枝端连线的方向角，一条线的角度，不需要标定）
                 → 同时算车与树的居中偏差，发给电控对中
② 查表 + 插值   → ψ 落在哪两档之间，就按比例插值，得到这一档四个点位的矩形位置与大小
③ 侧视相机      → 只在插值出来的矩形里数"果身像素占比"
                 → 超过阈值 = 这个点位有果；连续 N 帧都比较高才确认，一帧明显低就否决
```

**离散的 7 档为什么够用**：角度是连续的，但点位在画面里的移动，5° 之内近似线性，
两档之间按角度线性插值就能覆盖。一个档位的间隔内，点位的位移远小于矩形的尺寸，所以插值误差被矩形吃掉了。

**例外要老实标**：实测发现某个点位在某一档会被树干挡住（内挂点靠树干，很容易挡），
就在表里把这个"档 × 点位"标成 **不可观测** —— 那时宁可报"这里没有"，也不猜。猜错的代价是
一颗果按黄果处理（−20 分，抵掉两颗绿果），而漏一颗只是少 10 分。

---

## 5. 各方向要保证的事

- **机械**：相机相对车体**绝对固定**；侧视相机到树干轴的距离与高度要写进图纸（我们实测现在约 **22.5cm**、水平视场约 **99°**，覆盖 yaw 0° 够用，±30° 时靠内那侧会贴边，需要留余量）。
- **电控**：对中完成信号、四个点位的动作时序；我们只报"这个点位有果/没有果"，不给毫米坐标。
- **视觉**（我们）：7 档标定表 + 阈值 + 俯视角度和居中偏差。
